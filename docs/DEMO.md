Документы согласованы между собой: срок из протокола № 39 повторяется в отчёте и графике, ответственные из протоколов

## Вопросы и где находится подтверждение

Область поиска — «Все документы», если не указано иное. Основной режим — ответ пишет модель GigaChat по
найденным фрагментам, формулировки могут отличаться от «Ожидаемого ответа», но факты и источники те же
(каждая цитата сверяется с текстом документа). Колонка «Тип» описывает запасной режим без модели:
«подготовленный» — текст ответа написан заранее, но каждая цитата при ответе ищется в тексте документа;
«поиск» — ответ собран из найденных цитат без подготовки.

## Поведение при загрузке произвольного файла

- **PDF с текстовым слоем, DOCX, TXT, MD** — текст извлекается в браузере, документ получает статус
  «Готов к поиску». Дальше всё как с демо-документами: поиск находит фрагменты, GigaChat пишет ответ,
  браузер сверяет ссылки с текстом. Без модели — ответ из дословных цитат. Подготовленные ответы к своим
  файлам не применяются: они привязаны к демо-документам и включаются, только если цитаты найдены в тексте.
- **Конфиденциальность.** Сам файл никуда не отправляется: текст извлекается и хранится в браузере. В модель
  уходят только найденные фрагменты (до 8 по ~500 символов) через функцию на Vercel. Поэтому в прототип не стоит
  загружать документы с ограниченным доступом — для них функция должна работать в контуре компании.
- **Скан PDF без текста** — «Ошибка чтения: нет текстового слоя». OCR в прототипе нет.
- **Пустой файл, .doc, .xlsx, изображения и т. п.** — «Ошибка чтения» с объяснением и следующим действием.
- **Файл больше 15 МБ** — ошибка с объяснением.
- **Обновление страницы во время обработки** — демо-файлы дообрабатываются автоматически (их можно
  скачать заново), свои файлы получают ошибку «загрузите снова»: оригиналы файлов в браузере не хранятся,
  хранится только извлечённый текст.
